## Why a separate contract is necessary

The original 0.4.14 operation remains MANAGED_TOOLS. Its original product request
ID derives from the complete native request fingerprint, including the original
installer release. Ordinary helper plan reconstruction admits current signed
material and requires exact equality with that release. A successor cannot use
that ordinary route without either rejection or a changed product operation ID.
Both ordinary equality checks must remain intact.

The already reviewed service-folder preparation does not authorize execution of
an old plan by a new helper. This proposal adds that explicit, narrow authority
within the source increment; it authorizes no release, helper replacement,
registered-service stop or VM attempt.

## Proposed admission, with closed authority

1. Only the root helper can select the currently active private parent. An IPC
   caller may request inspection/recovery of that operation ID; it supplies no
   plan, path, version, fingerprint, command, credential or historical material.
   The authenticated IPC peer must match the originally registered operator and
   its current OS identity, still be an administrator, and own this exact
   operation. Recheck peer/account identity under the mutation lease. Neither a
   root peer nor root helper execution substitutes for this operator binding.
2. Independently admit the actual current signed executor/helper release against
   existing descriptor, companion and replay floors. Recheck it under the normal
   mutation lease immediately before effects. An old release is never current.
3. Load and freeze the original helper-owned selection, stored routesnapshot,
   parent, product authority and historical signed composition/release evidence.
   Every file must satisfy existing private ownership, modes, ACL, symlink,
   bounds, identity and strict JSON checks. Missing or altered proof denies.
4. Rebuild the original plan from those bytes. Require exact original intent,
   session, deployment, stable-plan fingerprint, activation fingerprint, selected
   components, provider targets, runtime slots and MANAGED_TOOLS receipts. The
   original release is provenance, not a new currency assertion.
5. Recompute the original native request fingerprint and original EP component
   operation ID. Match the exact existing product-owned CREATE request, selected
   artifact, service account, paths, service label and port. Do not replace the
   original selection, authority, parent or product request to make it match.
6. Create a private durable recovery admission that binds the original evidence
   hashes and request fingerprint to the independently current executor release,
   the same operation, OS account identity and closed recovery scope. Preserve
   the original admission and all replay anchors. Unknown scope is denied.
7. Expose a separate typed Python recovery admission. Normal native operation
   admission continues requiring current release equality. Recovery can only
   admit the reconstructed request matching that private recovery binding;
   caller-supplied flags or environment values cannot create authority.
8. Require missing EP terminal receipt, sole reserved worker, no competing
   operation and physical service/account/process quiescence. Preserve historical
   uncertainty. Perform bounded service preparation and replay only the same
   published product-owned CREATE. Existing healthy terminal success is a
   readback result, never another CREATE. Product receipts, pairing and independent
   readiness remain mandatory before completion.
   The only remaining saga steps allowed are the original, not-yet-executed Forge
   installation, original EP/Forge pairing and original readiness checks, with
   their original identities and evidence. No other install, update, repair or
   remove operation, provider login, credential transfer or credential route is
   admitted. An already completed step is verified from its correlated receipt;
   missing or conflicting proof never authorizes repeating it as new work.

## Qualification and denial gates

Qualify old-plan reconstruction and byte-identical old product operation ID;
current executor release drift; missing or changed selection/snapshot/authority;
composition/product drift; changed account identity; registered service without
PID; competing worker; existing terminal receipt; duplicate/replayed binding;
foreign IPC operator, lost administrator membership, operator identity drift;
interrupted admission publication and named-file substitution. Prove denials
preserve historical bytes and uncertainty. A source model or isolated file test
does not establish installed recovery PASS.

If any original evidence is missing or cannot reconstruct the exact request,
this route stays denied. A separately authorized product-supported alternative
must then be designed; no blind retry, new operation or hand-edited uncertainty
is part of this proposal.

## Integrated execution wiring (2026-10-13, source only)

The source increment now connects authenticated named-OS-peer XPC, the existing
helper-upgrade mutation lease, the exclusive provider host lease, original signed
material and physical preflight, sole durable historical effect reservation,
immutable operation-bound execution record, exact sealed current worker and an
independent signed-helper/enclosing-app CodeDirectory proof. Python consumes one

and dispatches only the unchanged dual CREATE. Historical authority supplies
provenance/routes; it never becomes current release authority. Currency checks
allow only the exact selected components, original product IDs, original parent
and installation credential binding. Ordinary current-release equality remains.

The existing component progress and product sagas drive EP, Forge, pairing and
readiness. Native receipt validation precedes an immutable separate historical
completion; original parent/journal bytes are retained. A closed frontend result
validates original request/operation, both READY components, pairing and readiness
before CLI success. A timeout denies but retains the child and both leases until
actual exit; excess output is drained without retention or logging. There is no
helper kill, automatic retry, uncertainty reset, credential export or new operation.
